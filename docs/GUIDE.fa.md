# راهنمای فارسی: ساخت ویدیوی ریلز هماهنگ با ضرب موسیقی

این راهنما برای کسی است که یک پوشه کلیپ و یک فایل موسیقی دارد و می‌خواهد یک ویدیوی کوتاه (ریلز، شورتز، تیک‌تاک، یوتیوب) بسازد که برش‌هایش روی ضرب آهنگ باشد. همهٔ فرمان‌ها و مسیرها به انگلیسی نوشته شده‌اند تا مستقیم کپی شوند. توضیح هر قابلیت به‌طور کامل‌تر در پوشهٔ [`references/`](../references/) هست و فهرست همهٔ فرمان‌ها در [`CLI.md`](CLI.md).

## ۱. این ابزار چه کاری می‌کند

شما به Claude می‌گویید چه ویدیویی می‌خواهید. Claude چند سؤال کوتاه می‌پرسد (قالب، طول، موسیقی، متن، حال‌وهوا، چه چیزی باشد و چه چیزی نباشد) و آن‌ها را در فایل `video-brief.md` می‌نویسد. بعد از تأیید شما، موتور این کارها را انجام می‌دهد:

1. فهرست‌برداری از کلیپ‌ها (`probe`) و ساخت شیت‌های شمارهٔ‌دار برای دیدن تصاویر (`sheets`)
2. اندازه‌گیری کیفیت هر کلیپ و پیدا کردن بهترین لحظه‌اش (`score`)
3. پیدا کردن ضرب، تمپو و لحظهٔ «دراپ» موسیقی (`beats`)
4. نوشتن طرح ویدیو در یک فایل کوچک JSON به نام EDL (`plan`)
5. رندر پیش‌نمایش و سپس نسخهٔ نهایی (`render`)
6. بررسی خودکار کیفیت (`qa`) و نگاه کردن به فریم‌ها

نکتهٔ اصلی: **هر تغییر یعنی ویرایش فایل EDL و رندر دوباره.** رندر فقط شات‌های تغییرکرده را از نو می‌سازد، پس اصلاح‌ها سریع‌اند.

## ۲. نصب

پیش‌نیازها: Claude Code، Python نسخهٔ 3.9 یا بالاتر (بدون هیچ کتابخانهٔ اضافه) و FFmpeg.

```powershell
winget install Gyan.FFmpeg
.\install.ps1
```

روی مک یا لینوکس: `./install.sh`. بعد یک نشست جدید Claude Code باز کنید و بنویسید `/mh-video-editor-skill`.

بررسی سلامت:

```bash
python "<skill-dir>/engine/scripts/mh_video.py" doctor
```

باید آخرش `READY` بیاید. فهرست قابلیت‌های اختیاری (متن، پایدارسازی، HDR ...) را هم نشان می‌دهد. اگر FFmpeg تازه نصب شده و پیدا نمی‌شود، اول `doctor` را اجرا کنید: موتور پوشهٔ winget را خودش جست‌وجو می‌کند.

## ۳. یک ویدیو از اول تا آخر

فرض کنید کلیپ‌ها در `D:/Trip/clips` و موسیقی در `D:/Trip/music.mp3` است. در مکالمه فقط بنویسید «با این کلیپ‌ها و این موسیقی یک ریلز 28 ثانیه‌ای عمودی بساز». Claude خودش این مراحل را انجام می‌دهد؛ اگر می‌خواهید دستی بروید:

```bash
python engine/scripts/mh_video.py probe "D:/Trip/clips" --work work
python engine/scripts/mh_video.py sheets --work work
python engine/scripts/mh_video.py score --work work
python engine/scripts/mh_video.py beats "D:/Trip/music.mp3" --out work/beats.json
python engine/scripts/mh_video.py need work/beats.json
python engine/scripts/mh_video.py pick --work work --count 39 --beats work/beats.json --out work/clips.txt
python engine/scripts/mh_video.py plan --scores work --beats work/beats.json --clips work/clips.txt --out work/video.edl.json --name trip
python engine/scripts/mh_video.py lint work/video.edl.json
python engine/scripts/mh_video.py render work/video.edl.json --preview
python engine/scripts/mh_video.py render work/video.edl.json --qa
```

از نسخهٔ 0.24 رندر نهایی تا آخر ده‌بیتی می‌ماند و رنگ‌ها دقیقاً همان رنگ فیلم خام بیرون می‌آیند. نسخهٔ قبلی رنگ‌ها را ۱ تا ۲ سطح تیره‌تر می‌کرد. با `--master` یک نسخهٔ HEVC ده‌بیتی هم برای آرشیو ساخته می‌شود و فایل اصلی همان H.264 معمولی می‌ماند:

```
python engine/scripts/mh_video.py render work/video.edl.json --qa --master
```

نکته‌ها:

- شیت‌ها را **با چشم** ببینید و کلیپ‌ها را خودتان انتخاب کنید. `pick` فقط پیشنهاد می‌دهد؛ انرژی‌ای که اندازه می‌گیرد «حرکت» است نه «هیجان»، و ممکن است نزدیک‌نمای غذا را از آفرود جلوتر بگذارد. با `--only` و `--exclude` محدودهٔ شمارهٔ کلیپ‌ها را مشخص کنید.
- `beats` اطمینان (confidence) و جایگزین‌های نصف/دو برابر تمپو را می‌گوید. اگر اطمینان پایین است، قبل از ادامه بپرسید.
- `lint` دو دسته پیام دارد: خطا (جلوی رندر را می‌گیرد) و هشدار (دربارهٔ اعتدال در افکت‌ها).

### انتخاب شات‌ها: اول داستان، بعد کلیپ

شات‌ها از روی «کدام تصویر قشنگ‌تر بود» انتخاب نمی‌شوند. مراحل:

1. یک جمله: ویدیو دربارهٔ چیست و بیننده چه حسی بگیرد؟
2. `story chapters`: سفر را از روی زمان فیلم‌برداری به **فصل‌ها** تقسیم می‌کند؛ فصل‌ها را نام‌گذاری و **وزن** می‌دهیم (وزن = اهمیت در داستان، نه حجم فیلم) و انرژی هر فصل (آرام، رو‌به‌اوج، اوج) را می‌نویسیم.
3. `story select`: تعداد شات هر فصل را طوری تقسیم می‌کند که فصل‌های پرانرژی روی بخش‌های بلند موسیقی بیفتند، کلیپ‌ها را با امتیاز (کیفیت، تناسب انرژی، صدا، آدم‌ها، دوربین کم‌استفاده، تنوع) انتخاب می‌کند و برای هر شات دلیل و دو جایگزین می‌دهد.
4. **استوری‌بورد را می‌بینید و تأیید می‌کنید**؛ بعد از آن `plan` و رندر.
5. `story audit`: ترتیب سفر، پوشش فصل‌ها، دوربین‌ها، حضور آدم‌ها و هماهنگی انرژی تصویر با موسیقی را کنترل می‌کند.

**عمق انتخاب (نسخه ۰.۱۶):**
- کلیپ‌های کوتاه‌تر از ۵ ثانیه هرگز استفاده نمی‌شوند؛ کلیپ‌های تاریک، تار، لرزان یا با کات داخلی هم با ذکر دلیل کنار گذاشته می‌شوند (`story exclusions`).
- اگر یک لحظه دو بار (یا با دو دوربین) فیلم شده باشد، فقط بهترین برداشت می‌ماند و بقیه رها می‌شوند.
- `story select` کل دنباله را یک‌جا بهینه می‌کند (نه شات به شات)، با سه روایت: `balanced`، `action`، `people` (گزینه `--variants`). `story refine` شروع هر شات را روی بهترین لحظهٔ داخل کلیپ می‌گذارد.
- افزونهٔ اختیاری و آفلاین `plugins/vision` (با `python plugins/vision/setup.py` نصب می‌شود و محیط مجازی خودش را دارد) چهره و آدم‌ها را پیدا می‌کند؛ یادداشت‌های خود شما همیشه برتر است.
- `story review` یک صفحهٔ HTML آفلاین می‌سازد: سه فریم از هر کلیپ و جایگزین‌هایش، دلیل انتخاب و منحنی انرژی؛ دکمه‌های نگه‌دار / جایگزین / حذف دارد و `decisions.json` می‌دهد. `story feedback` آن را اعمال می‌کند و سلیقهٔ شما را در `profile.json` به خاطر می‌سپارد (فقط از تصمیم‌های صریح؛ فایل متنی و قابل ویرایش است).
- `engine/tools/eval_selection.py --check` کیفیت انتخاب را روی یک کتابخانهٔ مصنوعی با پاسخ مشخص می‌سنجد.

**سنجیده‌شده روی سفر واقعی (نسخه‌های ۰.۱۷ تا ۰.۲۳):**
- **تشخیص چهره:** با مدل کوچک YuNet (`python plugins/vision/setup.py --model`، یک بار دانلود ۲۳۲ کیلوبایتی با بررسی SHA-256؛ بعد آفلاین) روی ۶۰ کلیپِ برچسب‌خورده درستی ۸۳ تا ۱۰۰٪ داشت؛ آشکارساز قدیمی (cascade) فقط حدود ۴۰٪. هر تشخیص به اندازهٔ اعتبار سنجیده‌اش حساب می‌شود و استوری‌بورد می‌گوید چند شات آدم‌دار را یادداشت‌های شما تأیید کرده‌اند.
- **تکراری‌ها:** فقط تکراری‌های قطعی حذف می‌شوند؛ شات‌های «شبیه هم» (کویر خیلی شبیه است) فقط علامت می‌خورند و انتخاب با شماست.
- **صفحهٔ بازبینی:** ویدیوی کوچک هر کلیپ قابل پخش است، **«Start here»** شروع شات را روی همان فریم می‌گذارد، خط زمانی کل ویدیو بالای صفحه است، تصمیم‌ها خودکار در مرورگر ذخیره می‌شوند. پوشهٔ `review_media` را کنار صفحه نگه دارید.
- **صدا (0.26):** صدای محیطی کلیپ‌ها جاهایی را که باد دارد یا صدایش خراب (clip) است خودکار کنار می‌گذارد. چون من صدا را نمی‌شنوم، این تشخیص‌ها موقت‌اند: `audio review --work work` صفحه‌ای با ۳۰ تکهٔ کوتاه صدا می‌سازد؛ گوش بدهید، بگویید چه می‌شنوید و خروجی را بگیرید تا `calibrate_audio.py` آستانه‌ها را با گوش شما بسنجد.
- **پایان واقعی آهنگ:** `music fit --beats work/beats.json --edl video.edl.json --preview work/joins` چند راه برای تمام شدن ویدیو با پایان خود آهنگ (به‌جای fade) پیشنهاد می‌دهد و برای هر کدام یک فایل صوتی کوتاه می‌سازد. گوش بدهید و با `--choose N --write` انتخاب کنید.
- **اصلاح زمان ضرب‌ها:** تا نسخهٔ 0.25 زمان ضرب‌ها ۰٫۲۳٪ دیرتر از واقعیت حساب می‌شد (در ثانیهٔ ۴۵ حدود ۰٫۱ ثانیه). `beats` را دوباره اجرا کنید؛ فرمان‌ها برای فایل‌های قدیمی هشدار می‌دهند.
- **«Play the storyboard»** در صفحهٔ بازبینی کل ویدیو را با زمان‌بندی واقعی و روی موسیقی پخش می‌کند، با همان انتخاب‌هایی که خودتان کرده‌اید، بدون هیچ رندری. این یک پیش‌نمایش خام است (بدون ترنزیشن و رنگ) تا قبل از تأیید، روند کل ویدیو را ببینید. برای اینکه موسیقی پخش شود، `story review` را با `--beats` اجرا کنید.
- **شروع قوی (`story hook`):** قدرت شروع فعلی را می‌سنجد و بهترین شات‌ها برای یک شروع پرهیجان (teaser) را با دلیلشان پیشنهاد می‌دهد؛ هر صحنه فقط یک پیشنهاد دارد. فقط کلیپ‌هایی رتبه می‌گیرند که در `shot-notes.json` نقش و حس دارند. اگر شروع با teaser را خواستید، در `chapters.json` مقدار `"hook": "teaser", "teaser_clip": N` را بگذارید و `story select` را دوباره اجرا کنید.
- **نقطهٔ شروعی که خودتان انتخاب می‌کنید** (Start here) در `profile.json` به خاطر سپرده می‌شود و آن کلیپ را نگه می‌دارد؛ `story select` بعدی همان شروع را به کار می‌برد و `story refine` هیچ‌وقت آن را جابه‌جا نمی‌کند.
- **نسخه‌های کوتاه‌تر بدون تأیید دوباره:** `story select --cut-from storyboard.json --duration 15` فقط از شات‌های تأییدشده و با همان نقطهٔ شروع، نسخهٔ ۱۵ یا ۳۰ ثانیه‌ای می‌سازد؛ اگر جا کم باشد، فصل‌های کم‌وزن با هشدار کنار می‌روند.
- **سلیقه برای همهٔ پروژه‌ها:** `story profile --work W --promote` گرایش‌های موضوع و نقش را به پروفایل سراسری می‌برد؛ تصمیم‌های مربوط به کلیپ‌ها در همان پروژه می‌مانند. `--forget-global` آن را پاک می‌کند.
- **موسیقی:** `pick_music.py --chapters chapters.json` آهنگ‌های خود شما را بر اساس هماهنگی انرژی‌شان با قوس داستان هم رتبه‌بندی می‌کند.
- اندازهٔ نما (دور/متوسط) اکنون ۶۳٪ با برچسب چشمی هم‌خوان است (قبلاً ۲۱٪)؛ نقش و حس شات از روی اندازه‌گیری قابل حدس نبود و ساخته نشد: Claude باید فریم‌ها را ببیند. همهٔ عددها در `docs/CALIBRATION.md`.

جزئیات: `references/story-selection.md`. با `sheets --only 100-140 --frames 3` شروع، وسط و پایان هر کلیپ را کنار هم می‌بینید.

## ۴. اعتدال در افکت‌ها

از تجربهٔ واقعی ساخت ویدیوی مرنجاب: نسخه‌ای با شش افکت هم‌زمان و ترنزیشن روی همهٔ برش‌ها «خیلی شلوغ» بود و نسخهٔ ساده‌تر «عالی». قاعده‌های پیش‌فرض که `lint` کنترل می‌کند:

- حداکثر 3 نوع افکت دیدنی در کل ویدیو (زوم ملایم، فلش سفید روی دراپ، شعلهٔ نور خورشید در پایان؛ **حرکت آهسته هم یکی حساب می‌شود**)
- ترنزیشن روی حداکثر نیمی از برش‌ها؛ بقیهٔ برش‌ها ساده و روی ضرب
- هر نوع ترنزیشن حداکثر یک بار و حداکثر 3 ترنزیشن از یک خانواده (مثلاً «اسلاید افقی»)
- اگر «افکت بیشتر» می‌خواهید، اول تعداد فعلی را ببینید و یک افکت را جایگزین کنید، نه اضافه

### کات و ترنزیشن: هر کدام یک «چرا» دارند

قبل از `plan`، Claude فوتیج را می‌خواند و یادداشت‌هایی در `shot-notes.json` کنار بریف می‌نویسد (نقش هر کلیپ، سوژه، جهت حرکت، اندازهٔ نما، حس، بهترین لحظه). بعد برای هر اتصال بین دو شات یک جدول می‌سازد: نوع کات و دلیلش.

- **کات روی حرکت**: دو شات که حرکتشان هم‌جهت است؛ نامرئی‌ترین کات.
- **هم‌شکلی (graphic match)**: دو جای متفاوت که شکل یا رنگ مشابه دارند.
- **کات تضاد (smash)**: جهش ناگهانی نور یا انرژی؛ فقط یکی دو بار.
- **کات‌اوی (cutaway)**: نمای جزئیات بین دو شات شبیه، برای جلوگیری از jump cut.
- **تنوع نما**: دور، متوسط، نزدیک؛ سه نمای هم‌اندازه پشت هم خسته‌کننده است.
- **ترنزیشن فقط وقتی چیزی می‌گوید**: گذر زمان یا مکان (محو)، ادامهٔ حرکت (اسلاید هم‌جهت با حرکت)، ضربهٔ دراپ (فلش سفید)، پایان (محو به سیاه). وگرنه کات ساده روی ضرب قوی‌تر است.

مراجع کامل: `references/cut-craft.md`، `references/transition-craft.md`، `references/footage-reading.md`. در گزارش نهایی Claude نوع کات‌ها و دلیل هر ترنزیشن را می‌نویسد؛ ترنزیشنی که دلیلی برایش نباشد حذف می‌شود.

## ۵. رنگ: تصحیح و سپس گرید

ترتیب درست: ۱) تبدیل HDR به SDR، ۲) تصحیح (نور، سیاهی و سفیدی، تعادل رنگ)، ۳) یک «لوک» (گرید) برای کل ویدیو.

```bash
python engine/scripts/mh_video.py color looks
python engine/scripts/mh_video.py color plan work/video.edl.json --match exposure
python engine/scripts/mh_video.py color plan work/video.edl.json --match exposure --write
python engine/scripts/mh_video.py color scope "D:/Trip/clips/a.mov" --at 3.2 --out scope.jpg
```

- `color plan` بدون `--write` فقط عددها و دلیلشان را نشان می‌دهد. عددها پیشنهادند؛ حتماً بازبینی کنید.
- **چند دوربین:** `color cameras --work W --edl video.edl.json --write` رنگ دوربین‌ها را به هم نزدیک می‌کند؛ فقط از کلیپ‌هایی که دو دوربین در یک دقیقه گرفته‌اند (همان نور)، و بقیه را با دوربینی که بیشتر فیلم گرفته هماهنگ می‌کند (`--reference` برای انتخاب دوربین دیگر). در سفر مرنجاب آیفون ۱۷ حدود ۵٪ قرمزتر و ۸٪ کم‌آبی‌تر از Osmo بود؛ آزمون روی روز دوم اختلاف را ۲۴٪ کم کرد. نور خود صحنه (غروب، آتش) دست نمی‌خورد. این را قبل از `color plan` اجرا کنید.
- لوک‌ها: `desert-gold` (کویر)، `teal-orange`، `golden-hour`، `cinematic-soft`، `film-faded`، `bleach-bypass`، `moody-dark`، `vivid-travel`، `clean-bright`، `bw-contrast`.
- در EDL: `"style": {"grade": {"look": "desert-gold", "strength": 0.9}}`. فایل `.cube` خودتان را هم می‌شود داد: `{"lut": "D:/luts/film.cube"}`.
- کلیپ‌های HDR آیفون: تبدیل پیش‌فرض اکنون `hable-203` است و از نسخه‌های قبل روشن‌تر درمی‌آید. برای بازتولید دقیق ویدیوهای قدیمی `"hdr_tonemap": "legacy"` بگذارید.
- یک لوک برای کل ویدیو؛ شدت را کم و زیاد کنید، نه نوع لوک را.

## ۶. پایدارسازی و حرکت آهسته

در EDL روی هر شات:

```json
{"clip": "D:/Trip/clips/a.mov", "span": [3.2, 4.5], "stabilize": "light"}
{"clip": "D:/Trip/clips/b.mov", "span": [4.5, 5.7], "speed": 0.5}
{"clip": "D:/Trip/clips/c.mov", "span": [5.7, 7.0], "speed": {"from": 1.0, "to": 0.4}}
```

- `stabilize`: مقدارهای `light` یا `strong`؛ برای شات‌های دست‌لرزان از پنجرهٔ ماشین. روی لرزان‌ترین کلیپ سفر واقعی، `light` لرزش را ۳۱٪ کم کرد. `plan --scores W --stabilize-shaky` آن را خودکار روی شات‌هایی می‌گذارد که لرزان اندازه‌گیری شده‌اند.
- حرکت آهسته با کلیپ 60 یا 120 فریم بر ثانیه کیفیت واقعی دارد. با کلیپ 30 فریم، موتور فریم می‌سازد (`mci`) و ممکن است لبه‌های تیز و سریع کمی تغییر شکل بدهند؛ شات‌های آهسته را کوتاه نگه دارید. `lint` اکنون با هشدار `slowmo-invented-frames` می‌گوید چند درصد فریم‌ها ساختگی است.

## ۷. متن فارسی

> پیش‌فرض: **هیچ متنی روی ویدیو گذاشته نمی‌شود** و در سؤال‌های بریف هم دربارهٔ متن پرسیده نمی‌شود. این بخش فقط وقتی استفاده می‌شود که خودتان متن بخواهید.

```json
"texts": [
  {"text": "کویر مرنجاب", "start": 0.4, "end": 3.0, "position": "title", "style": "title", "animation": "fade"},
  {"text": "مهر 1405", "start": 0.8, "end": 3.0, "position": "bottom", "style": "caption"}
]
```

- حروف به‌هم‌چسبیده، راست‌به‌چپ، ارقام فارسی و نیم‌فاصله درست نمایش داده می‌شوند (موتور libass).
- فونت: به ترتیب IRANSansFaNum، IRANSans، Vazirmatn، Sahel و ... هر کدام نصب باشد. `text fonts` فهرست را نشان می‌دهد. فونت جدیدی دانلود نمی‌شود؛ خودتان نصب کنید یا `MH_FONT_DIR` را تنظیم کنید.
- متن همیشه در «ناحیهٔ امن» می‌ماند تا زیر رابط اینستاگرام (بالای 12٪ و پایین 20٪ قاب) نرود.
- قبل از رندر **حتماً** پیش‌نمایش را ببینید و فونت‌ها را بررسی کنید؛ زیرنویس SRT هم وارد می‌شود:

```bash
python engine/scripts/mh_video.py text fonts
python engine/scripts/mh_video.py text preview work/video.edl.json --at 1.2 --out frame.png
python engine/scripts/mh_video.py text import-srt work/video.edl.json captions.srt
```

## ۸. نسخهٔ 16:9 و 1:1 از همان ویدیو

```bash
python engine/scripts/mh_video.py render work/video.edl.json --format youtube-16x9
python engine/scripts/mh_video.py render work/video.edl.json --all-formats
```

کلیپ عمودی در قاب افقی با پس‌زمینهٔ تار (`blur-fill`) نمایش داده می‌شود. برای شاتی که سوژه‌اش وسط قاب نیست `focus` بدهید: `"focus": [0.3, 0.5]`. برش‌ها و ترنزیشن‌ها در همهٔ قالب‌ها یکسان‌اند. فایل‌ها با پسوند `_9x16`، `_16x9` و `_1x1` ذخیره می‌شوند.

## ۹. صدا

- **whoosh** (صدای عبور) روی ترنزیشن‌های متحرک، با جهت حرکت تصویر؛ موسیقی زیر آن خودکار کم می‌شود: `"sound_design": {"whoosh": true}`.
- **صدای محیط کلیپ‌ها** (باد، موتور) زیر موسیقی، با ترازی که نسبت به موسیقی تنظیم می‌شود: `"ambient": {"level_db": -14}`.
- بلندی نهایی روی -14 LUFS تنظیم می‌شود (دو مرحله اندازه‌گیری)، و پیک واقعی زیر -2 dBTP می‌ماند.
- **من صدا را نمی‌شنوم.** فقط بلندی، پیک و سکوت را اندازه می‌گیرم. وجود whoosh و صدای محیط را شما باید با گوش تأیید کنید.

## ۱۰. گیت کیفیت (`qa`)

```bash
python engine/scripts/mh_video.py qa work/trip.mp4 --edl work/video.edl.json --scores work
```

نتیجه یکی از `PASS`، `PASS WITH WARNINGS` یا `FAIL` است. چیزهایی که بررسی می‌شود: فریم سیاه یا سفید ناخواسته، رنگ بنفش یا سبز غیرعادی، فریز شدن، جای برش‌ها نسبت به EDL، بلندی و پیک صدا، سکوت، حجم فایل، پرش ناگهانی روشنایی بین شات‌ها، و حسابرسی افکت‌ها. هر هشدار زمان دقیق دارد؛ همان لحظه را در شیت یا فریم‌ها **ببینید**. گیت دربارهٔ سلیقه، ترکیب‌بندی و داستان نظر نمی‌دهد.

## ۱۱. استفادهٔ خودکار با agent

بعد از تأیید `video-brief.md` می‌توانید کار را به agent بسپارید: `mh-video-editor`. این agent نمی‌تواند سؤال بپرسد، پس بدون brief تأییدشده فوراً با `NEEDS_DISCOVERY` متوقف می‌شود. نتیجه: ویدیو به‌علاوهٔ یک گزارش کوتاه (چه ساخته شد، چه چیزی بررسی شد، چه چیزی بررسی نشد، تعداد افکت‌ها و ترنزیشن‌ها).

## ۱۲. دستورهای تغییر بعد از تحویل

تغییرها را **لایه‌به‌لایه** بخواهید: اول کلیپ‌ها، بعد ترنزیشن‌ها، بعد افکت‌ها، بعد صدا. نسخه‌های قبلی را نگه دارید (`trip_v1.mp4` ...). کلیپ‌هایی را که تأیید کرده‌اید «قفل» اعلام کنید تا تغییر نکنند.

## ۱۳. عیب‌یابی سریع

| مشکل | کار |
|---|---|
| `FFmpeg not found` | `winget install Gyan.FFmpeg` و اجرای دوبارهٔ `doctor` |
| پیام `ffmpeg-missing` | FFmpeg نصب‌شده فیلتر لازم (مثلاً `ass` برای متن یا `vidstabdetect`) را ندارد؛ نسخهٔ کامل را نصب کنید |
| حروف فارسی جدا یا چهارگوش | فونت مناسب نیست؛ `text fonts` را ببینید یا فونت نصب کنید |
| رندر کند است | بار اول کند است؛ بعد از آن کش کار می‌کند. `--preview` برای نگاه سریع |
| خطا بدون توضیح | `MH_DEBUG=1` را تنظیم کنید و فرمان را دوباره اجرا کنید |

فهرست کامل در [`TROUBLESHOOTING.md`](TROUBLESHOOTING.md).

## ۱۴. محدودیت‌های صادقانه

- صدا را نمی‌شنوم؛ فقط اندازه می‌گیرم.
- انتخاب کلیپ و داستان با دیدن شیت‌هاست؛ امتیازها راهنما هستند نه حکم.
- حرکت آهسته با کلیپ 30 فریم، فریم‌های ساختگی دارد.
- ابزار برای ساخت ویدیو با هوش مصنوعی یا ترکیب‌بندی سنگین (کامپوزیت) نیست.
- تست‌ها با کلیپ‌های مصنوعی ساخته شده‌اند؛ آستانه‌های انتخاب روی یک سفر واقعی (۴۸۶ کلیپ) سنجیده شده‌اند و یک سفر نمی‌تواند همه‌چیز را ثابت کند. روی دستگاه‌ها و نسخه‌های FFmpeg دیگر کامل امتحان نشده‌اند.
- آشکارساز چهره بدون مدل YuNet ضعیف است (حدود ۴۰٪ درست)؛ یادداشت‌های شما همیشه برتر است.
